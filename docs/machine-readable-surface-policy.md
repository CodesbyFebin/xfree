# XFree machine-readable surface policy

Last reviewed: 2026-08-23

XFree does **not** create machine-readable files simply to reach an arbitrary file count. A public machine-readable endpoint must correspond to a real protocol, real site capability, or truthful operational disclosure. Empty, fabricated, duplicate, or pseudo-standard endpoints can create crawler ambiguity and maintenance risk.

## Supported production surfaces

These files/endpoints have a concrete purpose in XFree today:

- `/robots.txt` — crawler access policy and canonical sitemap discovery.
- `/sitemap-index.xml` — canonical sitemap index.
- `/sitemap-pages.xml` — indexable static/category/pillar pages.
- `/sitemap-tools.xml` — published, implementation-backed tool pages only.
- `/sitemap-guides.xml` — reviewed guide pages.
- `/sitemap.xml` — compatibility aggregate sitemap.
- `/rss.xml` — content feed; not advertised as a sitemap.
- `/llms.txt` — concise AI-readable overview/discovery surface.
- `/llms-full.txt` — fuller AI-readable content surface.
- `/ai.txt` — XFree's own AI/crawler policy statement; treated as a site policy file, not as a Google ranking protocol.
- `/openapi.json` — API contract for actual public endpoints.
- `/tools.json` — published tool catalog.
- `/capabilities.json` — machine-readable capability summary.
- `/entities.json` — entity identity metadata.
- `/knowledge-graph.json` — real XFree entity relationships generated by the discovery pipeline when present.
- `/health.json` — static build metadata.
- `/api/health` — runtime liveness endpoint.
- `/.well-known/security.txt` — RFC 9116-style security contact/policy surface.
- `/ads.txt` — IAB/Google advertising seller authorization.
- `/site.webmanifest` — PWA/web-app manifest.
- `/apple-touch-icon.png` and favicon assets — platform/browser identity assets.
- IndexNow key file — search-engine change-notification verification.

## Files XFree will not fabricate

The following proposed files are **not** automatically created unless the underlying capability/data becomes real and there is a documented consumer:

- `/.well-known/whois.json` — not a substitute for registrar/RDAP/WHOIS data.
- `/.well-known/dnssec.json` — DNSSEC trust must be established in DNS, not asserted by an arbitrary JSON file.
- `/billing.json` — can expose sensitive/commercial information and has no SEO requirement.
- `/analytics.json` — not an AdSense or search requirement; analytics disclosure belongs in privacy documentation unless a real API contract exists.
- `/schema/product.json`, `/schema/claimreview.json`, or other detached schema files — structured data belongs on the relevant canonical pages and must describe real content/entities. XFree does not publish schema types it cannot substantiate.
- `/sitemap-news.xml` — only appropriate for eligible news content and should not be generated for ordinary utility pages.
- `/sitemap-video.xml` — only appropriate when XFree publishes qualifying video pages with the required metadata.
- `/hreflang.xml` or locale JSON files — only when translated canonical content actually exists and is maintained.
- `/.well-known/keys.txt` — only if XFree publishes and rotates a real public verification key.
- `/sponsors.txt` or `/partners.txt` — only if real sponsor/partner relationships need disclosure.
- query-string manifest clones such as `/manifest.json?theme=dark` — not treated as separate trust files; one maintained web manifest is preferred.

## Duplicate-file rule

A proposed checklist that counts the same resource multiple times (for example `llms.txt`, `llms-full.txt`, `ai.txt`, `security.txt`, or `manifest.json`) does not increase authority. XFree keeps one canonical resource for each function.

## Search and AdSense rule

None of `ai.txt`, `llms.txt`, `humans.txt`, arbitrary JSON schema files, or a high machine-readable file count guarantees Google ranking, AI citations, or AdSense approval. Search/monetization decisions depend on actual content quality, crawl/index correctness, policy compliance, user experience, and other system signals.

Machine-readable surfaces are maintained because they make XFree easier to inspect and integrate—not as synthetic ranking signals.
