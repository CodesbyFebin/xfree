# XFree adoption sprint

Order of operations:

1. **Recipes first** — make developers able to run, inspect, copy, and discuss a concrete workflow.
2. **GitHub positioning** — lead with Try → Inspect → Contribute and verified architecture facts.
3. **Technical launch** — Show HN and a LocalLLaMA engineering post only after the live recipe URLs are deployed and tested.
4. **Awesome-list outreach** — target lists that fit browser developer tools, TypeScript, WebGPU/WebAI, privacy, and local AI. Do not claim self-hosting until a documented self-hostable distribution exists.
5. **Build in public** — recurring releases should link to concrete recipes, tools, tests, or architecture improvements rather than generic platform announcements.

## Verified claims to use

- 60 published tool routes.
- 50 tools in the governed local-tool expansion batch.
- 100 allowlisted local Studio engines.
- 8 versioned starter workflow recipes.
- Deterministic tool chaining.
- Optional WebGPU/WebLLM planning behind the same allowlist boundary.
- No XFree signup required for published tools and starter recipes.
- PWA caches same-origin application assets; model downloads are excluded from the service-worker cache.
- Optional cloud/API features exist and are disclosed separately.

## Claims to avoid

- “The entire platform is 100% client-side.”
- “Zero network dependency.”
- “25,000 live tools.”
- “Best / fastest / most private” without a disclosed benchmark or comparison method.
- Fake stars, users, execution counts, ratings, or contributor activity.
- Guaranteed ranking, traction, virality, or community acceptance.
